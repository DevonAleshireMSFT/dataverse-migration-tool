# Architecture Decision Records

This directory contains Architecture Decision Records (ADRs) for the Dataverse Migration Tool.

For the current product direction and top-level layer map, see the [Product Vision and Architecture Overview](../product-vision.md).

We use Michael Nygard's ADR format: each record captures the context, the decision, the options considered, and the consequences. ADRs should be short, dated, immutable after acceptance, and superseded by a new ADR when the architecture changes.

## Process

1. Copy `adr-template.md` to `ADR-###-short-kebab-title.md`.
2. Use the next sequential ADR number.
3. Set a status such as `Proposed`, `Accepted`, `Deprecated`, or `Superseded by ADR-###`.
4. Describe the decision in terms of forces and trade-offs, not implementation preferences alone.
5. Link future decisions back to the ADRs they supersede or refine.
